# materials

## Summary
I mapped the materials, textures and shaders read-only and changed nothing in the project. The only file written is the notes file (181 lines, every claim cited to file:line). Five problems account for most of the bad look. (1) UV stretch: architecture is scaled Unity cubes with UV0 and 1x1 tiling, so one 2048 texture is spread over faces up to 146 m (14-19 texels/m). (2) Props: all 40 prop FBXs use HDRP's automatic FBX material (base + normal, metallic 0, flat smoothness). The mask map shipped with each prop is never bound, because no FBX has a material remap. (3) Foliage: grass and fern cards are opaque and single-sided, with no alpha clip, translucency or wind. Their textures are 84-93% transparent, so they likely draw as dark rectangles. (4) Terrain: all 4 layers bind the _MaskMap_Wet masks because of a last-match-wins loop, so the ground is always glossy. The Grass layer texture is straw-coloured. (5) The custom shaders are unlit and tuned to one exposure: the ocean and stream material has _LuminanceScale 2600 and goes white at night. Separately, the wetness/rain globals are overwritten to 1.0/0.85 every frame, and nothing reads the lightning global. AtmosphereController.cs was being edited live at 01:09, so its line numbers in the notes refer to that version.

## How to
- Entry point: CLI `cretacea build_all_scenes` -> CretaceaWorldAssembler.BuildAllScenes (CretaceaWorldAssembler.cs:170-208) creates ONE `new WorldMaterialPalette()` (:193) whose ctor (WorldMaterialPalette.cs:85-130) rebuilds every World material, then SaveAssets (:208).
- Material helpers: `GetOrBuildPbr(name, string[] folderHints, Color fallbackTint, float metallic, float smoothness)` (WorldMaterialPalette.cs:132), `GetOrBuildEmissive(name, Color, float nits)` (:163), `CreateTextureQuadMaterial(name, stem, emissive, intensity, tint)` (:188), `CreateDecalMaterial(name, albedoStem, normalStem, tint)` (:218); all funnel PBR through `CretaceaPbrImporter.CreateOrUpdateHdrpLitMaterial(path, base, mask, normal, emissive, metallic, smoothness, normalScale)` (CretaceaPbrImporter.cs:460).
- Idempotency: an existing .mat is loaded and only the props the palette manages are re-applied. Remaps (forced to 0..1 when a mask is found), _NormalScale (1.0), _Smoothness/_Metallic, emissive values, and the glass/chainlink/decal props are reverted on every build. _UVBase, _TexWorldScale, texture tiling, the _BaseColor of textured mats, detail maps and alpha/double-sided on PBR mats survive. Put look changes in the code, or limit hand edits to the props that survive.
- Texture-set binding is substring matching over the whole path under Assets/Art/Textures (FindTextureSet, WorldMaterialPalette.cs:526-550), and the first match wins. Hints like "concrete", "rust" and "moss" pick unexpected sets: ConcreteFloorWet=concrete_cracked_ext, RustedIron=metal_corrugated_rusty, FoliageDark=moss_ground. To be safe, pass exact folder names.
- Whenever code sets HDRP keyword-driven props (_UVBase, alpha clip, SSS/translucent MaterialID, double-sided, transparency), call `UnityEngine.Rendering.HighDefinition.HDMaterial.ValidateMaterial(mat)`. It is public in the installed package (Runtime/Material/MaterialExtension.cs:369); the project never calls it today.
- Prop and foliage FBX materials are embedded sub-assets (materialImportMode 2, materialLocation 1, externalObjects {}), produced by HDRP's FBXMaterialDescriptionPostprocessor.cs:25-154. To change them persistently, use `ModelImporter.AddRemap(new AssetImporter.SourceAssetIdentifier(typeof(Material), "M_<prop>"), mat)` + SaveAndReimport. Copy the 5 character metas (e.g. visitor_man.fbx.meta:6-10), and remap the 64 LOD1/LOD2 FBXs too.
- Hand-authored materials live in Assets/Settings/Rendering (CCTV, DawnOcean, Rain*, WetPuddle*). The palette only loads them, and CretaceaPbrImporter ignores Assets/Settings (CretaceaPbrImporter.cs:25), so they are safe to edit by hand. Terrain layers are Assets/Art/Terrain/TL_*.terrainlayer, rewritten by Zone4_TerrainJungleAndDawnCoastBuilder.cs:212-278 on each build.
- CretaceaPbrImporter: normal maps are imported as OpenGL with no green flip; I confirmed that matches the world texture sets via height-gradient correlation. Albedo textures use default compression (BC1/BC3). Maximum size is 2048 unless the path contains /dinosaurs/,/hero/,/4k/,/flashlight/ etc.; the 4096 hero props and trees are currently capped. Textures under /ui/ and /maps/ become mip-less Sprites, which matters for the 3D map boards.
- Wetness: only the custom shaders read the globals; HDRP/Lit does not. The WetPuddleOverlay material is on no renderer. StormRainOcclusionController.Update (StormRainOcclusionController.cs:79-96, values in prefab Assets/VFX/PF_StormRainSystem.prefab:50-51) rewrites _RainIntensity/_GlobalWetness every frame. Its setters are called only by the editor chapter-jump tool (CretaceaWorldAssembler.cs:1682-1683, :1795), so CLI captures hide the runtime value.
- MainWorld.unity is binary-serialized (6.07 MB), so grep on scene contents does not work. Use the live dumps or editor queries to find which renderers use which material.
