# Notes: runtime rendering + player view (Cretacea: Blackout, Unity 6000.6.9f1 / HDRP 17.6)

Project root: ~/CretaceaBlackoutUnity (all paths below relative to it). Read-only mapping, 2026-11-20.

## 0. TL;DR for the look pass

1. Player rig, cameras, viewmodel volume and rain are built by `CretaceaWorldAssembler.BuildPlayerRigAndCameras` / `EnsureViewmodelCustomPassVolumeInScene` / `InstantiateStormRainSystem` (Assets/Editor/WorldBuilder/CretaceaWorldAssembler.cs:420-672). Change values there or in the prefabs/scripts, never in the scene.
2. Glove looks light grey because its albedo is ~0.006 (dark texture x 0.15 tint), so rough grey specular dominates, fed (probably) by the stale lights-ON corridor reflection probe plus a 4.5 lm bounce fill near the hand. Outdoors (Escape shot) the same glove reads black. Not a texture problem.
3. The viewmodel custom pass (BeforePostProcess, depth clear) gets lighting/exposure/post but no fog, SSAO, contact shadows, SSR or motion vectors (TAA smear risk), and uses the world FOV (78 vertical = ~110 horizontal, plus sprint/crouch FOV changes).
4. Rain indoor occlusion relies on `Camera.RenderWithShader`, a Built-in-RP feature: under HDRP the roof height map is (almost certainly) never written, so it rains inside (visible in the corridor shot). Rain and CCTV shaders are unlit fixed-luminance emitters (`x GetCurrentExposureMultiplier()`, ~1.35 and 8 nits) balanced by eye at EV 0.6; they will jump when exposure changes (same for the 14-nit flashlight LED emissive).
5. `StormRainOcclusionController` re-sets `_RainIntensity`/`_GlobalWetness` every frame (1.0/0.85) and overrides AtmosphereController's per-preset values, in the port and in the lead's rewrite.
6. Lightning is a shadowless directional light: it flashes inside sealed rooms.
7. Camera: TAA Medium only; dithering OFF (banding in dark gradients), stop-NaNs OFF, dynamic resolution never allowed (STP unused). Motion blur 0.5 comes from the HDRP default profile.
8. Interior zones are audio-only; no per-room exposure/fog/grade. Room probes are Realtime OnEnable and never refresh after power changes.
9. The port's single runtime profile (copied from Preset_BlackoutStorm on every build) graded day and night the same; Preset_* assets were only used by the edit-mode chapter jump. The lead's 5-volume rewrite (section 4a) replaces that at runtime.

- Rig pose: prefab root identity; `FPS_GlovedArm` / `FPS_Flashlight_Armature` / `TacticalFlashlight_Held` are FBX nodes with rot -90 X and scale 100 (prefab :28-30, :968-970, :1001-1003); mesh `Assets/Art/Props/Flashlight/flashlight_fps_rig.fbx`; Animator controller `Assets/Animations/Player/AC_FlashlightFpsRig.controller` (prefab :279). - Materials (all HDRP/Lit, Assets/Art/Materials/Props/Flashlight/): `M_FPS_GlovedArm` base map fps_arm_BaseColor.png (sRGB) x tint (0.14, 0.15, 0.175), mask map + normal present, smoothness remap max 0.28 (M_FPS_GlovedArm.mat:39-84, :208-209, :248); `M_FPS_JacketSleeveExt` no textures, (0.045, 0.055, 0.07), smoothness 0.2 (:206, :246); flashlight body `M_Flashlight_AnodizedBody` base map x white, mask map, metallic 0 (:206, :264); `M_Flashlight_LED_Emitter` emissive (14, 13.44, 12.32) (:267); `M_Flashlight_GlassLens` transparent, alpha 0.16, smoothness 0.96 (:242-265); plus RubberGrip, ReflectorChrome, PowerLED_Red.

Why the glove reads light grey and large in shots_base/play_Corridor_5s.jpg (screenshot checked):
1. It is SPECULAR, not albedo. fps_arm_BaseColor.png averages sRGB (52,57,59) = linear ~0.04 (my PIL measurement), then x tint 0.14-0.175 => effective albedo ~0.006 (near-black, darker than coal). Diffuse is therefore negligible and the rough dielectric specular (F0 0.04, smoothness <= 0.28) dominates ~7:1, which is grey/white by definition => the arm reads as desaturated light-grey "dusty plastic".
2. What feeds that specular: (a) most likely the corridor's box reflection probe: room probes are Realtime + `RealtimeMode.OnEnable`, multiplier 0.45 (Assets/Editor/WorldBuilder/WorldArchitectureKit.cs:757-768), captured once at scene enable (main lights ON, emergency OFF, before the blackout) and never refreshed, so every rough surface keeps reflecting a lit white corridor. Evidence: in shots_base/play_Escape_5s.jpg (outdoors, no box probe; checked) the same glove reads near-black with only knuckle highlights. Not verified directly (disable the probe in the corridor and compare). (b) `FlashlightBounceFill` 4.5 lm point (0.36 cd) sits 0.06 m beyond the muzzle (prefab :666-668, scale-100 parent; muzzle is 0.21 m up Flashlight_Bone, :936), roughly 0.15-0.3 m from the fingers => ~4-16 lux, a highlight on the knuckles. At fixed EV 0.6 the pre-exposed white point is 1.8 nits (1.2*2^EV), so a few tenths of a nit of specular already read light grey after ACES.
3. No AO / contact shadows / fog / SSR on the viewmodel (see above) => flat, evenly lit, high-contrast "cut-out" against the hazy scene.
4. Size: rig pivot is only 0.34 m in front of the eye and 0.18 m right (CretaceaWorldAssembler.cs:465) at FOV 78 vertical (~110 deg horizontal at 16:9); the forearm runs to the lower-right corner, so the hand fills the lower-right quadrant. A wider FOV makes it smaller, so the size comes from pose/offset, not FOV.
Fix direction: set the glove tint to white or ~0.8 (the texture alone is already a black glove at ~0.04); the sleeve value (0.045-0.07) is fine for dark fabric but it has no textures at all; give the glove smoothness ~0.35-0.45 for leather; remove the bounce fill or drop it to <=0.5 lm on its own light layer; re-render the room probes after power changes (or make them baked/OnDemand and call RequestRenderNextUpdate from LightGroupController); move the pivot to ~(0.14, -0.17, 0.42) and/or render with a fixed ~55-60 deg vertical viewmodel FOV.

Colour = tint x `_Brightness` x `GetCurrentExposureMultiplier()` (:117), i.e. the streak is a fixed 1.0-1.35 "nit" emitter: ~0.55 pre-exposed at EV 0.6 (uniform grey-blue scratches even in pitch black, not lit by flashlight or lamps), invisible at day EVs. Materials: MAT_RainStreaks brightness 1.35, colour (0.72,0.82,0.94,0.38), softness 1.6; MAT_RainSplashes 1.25, (0.78,0.86,0.96,0.55) (Assets/Settings/Rendering/MAT_Rain*.mat:32-38).
- Occlusion: a hidden ortho camera `__RainOcclusionCam` renders layer 13 with `Camera.RenderWithShader(RainOcclusionHeight)` into a 512^2 RFloat RT (StormRainOcclusionController.cs:139-177); the rain/wet shaders discard fragments below the stored roof height (CretaceaRainParticle.shader:88-99, CretaceaWetSurface.shader:133-145). Replacement-shader rendering is a Built-in-RP feature; under HDRP this call almost certainly does not produce the height map (the RT is never cleared to the -9999 "no roof" value either), and the lead's corridor shot shows rain streaks INSIDE the staff corridor plus one huge clamped near-camera streak at top centre. Treat indoor occlusion as broken (verify the RT in the Frame Debugger). HDRP-native replacements: a CustomPass on a dedicated camera with `CustomPassUtils.RenderFromCamera(..., overrideMaterial)` writing world Y, or simply per-room "dry" volumes that kill emission (rooms already have InteriorZoneVolume triggers), or VFX Graph rain with depth-buffer collision.
- Global fight: `StormRainOcclusionController.Update` re-sets `_RainIntensity`/`_GlobalWetness` from its own fields every frame (:94, :179-185), overwriting AtmosphereController's per-preset values (current file `ApplyKeyLook`, AtmosphereController.cs:439-440 - the lead's rewrite has the same conflict). StoryDirector never touches the rain controller (grep), so in normal play wetness stays 0.85 and splash rate 320/s even in GoldenDay/Dawn (splashes use `ParticleSystem.Emit` regardless of AtmosphereController stopping the system - not verified whether they render while stopped). Only the chapter-jump tool sets `rain.RainIntensity/GlobalWetness` (CretaceaWorldAssembler.cs:1680-1684, :1792-1797).
- Cost: 1800 streaks/s x ~1.1 s = ~2000 live billboards, overdraw small; splash raycasts <= 24/frame; occlusion re-render each 6 m of travel (cheap, if it worked). `lobbyBrokenSkylightRainSystems` (AtmosphereController.cs:47, used :318-330) is never assigned by any builder (grep of Assets/Editor), so `SetLobbySkylightRain` (StoryDirector.cs:300, :777) does nothing.
