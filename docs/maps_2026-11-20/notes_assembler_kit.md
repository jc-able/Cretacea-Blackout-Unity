It will wipe: any edit made in either scene, any edit to the two runtime profiles, the DawnCoast fields above, palette material colour/smoothness/metallic/emissive values, and the EditorBuildSettings scene list.

**Geometry primitive = Unity cube, scaled. UVs are NOT world-scaled.**
- `CreateBox(Transform parent, string name, Vector3 localPos, Vector3 size, Material mat, bool addCollider = true, Vector3? euler = null)` K:926-952. `GameObject.CreatePrimitive(Cube)`, `localScale = size`, layer Environment (K:941), sharedMaterial = mat, collider destroyed if !addCollider. No static flags, shadows default On. UV0 = built-in cube 0..1 per face, so every face shows exactly ONE texture repeat stretched over its full size (38x51 m lobby floor, 79.6 m corridor walls, 0.065 m jambs all get 1 tile). Every palette material in the live dump has `tile=(1.00,1.00)` and `uv=0` (dump/materials.txt lines for MAT_ConcreteBoardform, MAT_DarkPaintedMetal, MAT_ConcreteFloor...). No triplanar, no planar mapping, no per-box UV generation anywhere in the kit.
- `ApplySurface(GameObject go, SurfaceType surface, WorldMaterialPalette palette)` K:954-968: adds/updates `SurfaceTag.surfaceType` and sets collider PhysicsMaterial (`palette.GetSurfacePhysicsMaterial`). No visual effect.

**Lights (the root cause of the clipping)**
- `BuildHdrpLight(Transform parent, string name, Vector3 worldPos, Vector3 eulerAngles, LightType lightType, Color color, float intensityLumens, float range, LightGroupId lightGroup, float volumetricDimmer = 1.0f, bool castShadows = false, float spotOuterAngle = 60f, float colorTempK = 5500f, int sequenceOrder = 0, bool rotatingBeacon = false, bool pulsingEmergency = false, float blackoutBackupFactor = 0f, Renderer[] pairedEmissives = null)` K:657-704.
  - Sets `light.intensity = intensityLumens` (K:684) but NEVER sets `light.lightUnit`. Every kit light in the live dump reads **Candela** (98 of 104 lights = 92 kit lights + 6 `StatusLight` 18 cd points made by Zone3_SubstationAndYardBuilder.cs:242-247, which also never set a unit; only flashlight/fill/charging LED are Lumen, key/lightning Lux; dump/lights.txt). So values authored as lumens are applied as candela: a point light gets 4*pi = 12.6x the intended flux (corridor 620 -> ~7,800 lm; Lobby_SkylightDayFill 85,000 cd ~ 1.07 M lm), spots far more. This alone explains "lit = clipped, unlit = black".
  - `useColorTemperature = true`, `colorTemperature = colorTempK` (default 5500 K, most callers leave it), `color` acts as a filter on top; `hd.SetColor(color, colorTempK)` K:698. Spot: `spotAngle = outer`, `innerSpotAngle = 0.55*outer` (K:689-693). Shadows `Soft` or `None` (K:688; 20 of 104 lights cast shadows); shadow resolution/filtering not set (HDRP defaults). `affectsVolumetric = volumetricDimmer > 0.01`, `SetLightDimmer(1, volumetricDimmer)` (values up to 2.5) K:696-697. Contact shadows forced ON for every light (K:699-700). No light layers, no cookies, no IES, no `range`-based fade tuning, no `luxAtDistance`.
  - Always calls `AttachLightGroupMember(go, lightGroup, new[]{light}, pairedEmissives, sequenceOrder, rotatingBeacon, pulsingEmergency, blackoutBackupFactor)` K:702.
- `AttachLightGroupMember(GameObject target, LightGroupId groupId, Light[] lights = null, Renderer[] emissives = null, int sequenceOrder = 0, bool rotatingBeacon = false, bool pulsingEmergency = false, float blackoutBackupFactor = 0f)` K:706-740: get-or-add; REPLACES managedLights / emissiveRenderers arrays when non-null. Runtime (Assets/Scripts/Core/LightGroupMember.cs:90-96) caches `l.intensity` at start as the base and multiplies by a power factor (:146), emissives via MPB `_EmissiveColor = base * factor` (:150-158). So fixing the serialized intensity/unit in the kit flows straight through the runtime system.
- `BuildIlluminatedSign(Transform parent, string name, Vector3 localPos, Vector3 localEuler, Vector2 size, Material signMat, LightGroupId groupId)` K:809-827: one 0.04 m `SignPlate` box with an emissive material (EmissiveRed/Green), registered as LightGroupMember emissive; no text, no light, no texture.

## 7. Look-pass risks and suggested fixes (summary, most important first)

1. **Light unit bug (K:684).** `BuildHdrpLight` writes "lumens" into a Candela light (98/104 lights Candela, dump/lights.txt). Fix: `light.lightUnit = LightUnit.Lumen;` before `light.intensity = ...`, and for spots choose `light.enableSpotReflector` explicitly. That property is on `Light` in HDRP 17 (package HDAdditionalLightData.cs:2718 reads `legacyLight.enableSpotReflector`); HDRP's own default for point/spot is Lumen (HDAdditionalLightData.cs:2913-2917). Same fix for Zone3 StatusLight (Zone3_SubstationAndYardBuilder.cs:242-247). Then rebalance against exposure. At fixed EV100 0.6 / 1.2 the Night/Blackout pixel scale is 1/(1.2*2^EV) = 0.55 / 0.36, so mid-grey on a 30-50 % albedo surface needs only about 2-5 lux. As real lumens the corridor 620 lm at 3 m gives ~5.5 lux (good), but lobby 58,000 lm spots / 85,000 lm fill and Talon 28,000 floods remain day-scale. The kit has ONE serialized intensity per light (scaled only by the LightGroupMember power factor, Scripts/Core/LightGroupMember.cs:146), so day-scale lights blow out at night. Either give LightGroupMember / AtmosphereController a per-preset multiplier, or author day-only lights in a group that is off at night.
2. **Stretched textures everywhere (K:935-941 + palette tile 1x1).** Cube UVs mean one texture repeat per face at any size. Fix A (recommended for static architecture): set the architecture materials to HDRP Lit triplanar/planar world mapping (`_UVBase` = 5 Triplanar / 4 Planar, `_ObjectSpaceUVMapping` = 0, `_TexWorldScale` ~ 1/tile_m; property names in package Runtime/Material/Lit/Lit.shader:157-159). Run `HDMaterial.ValidateMaterial` after scripted changes. Moving door leaves would "swim", so keep them on UV0 or give doors their own material. Fix B: make `CreateBox` emit a generated box mesh with UV = face size / tile metres (cache by rounded size; persist like Zone4_TerrainJungleAndDawnCoastBuilder.cs:674 does). Either fix also cures the chainlink span (K:902), plinths and menu backdrop boxes.
3. **No bounce light / no interior volumes.** No lightmaps, APV, light probes or local Volumes (section 5; A:719-723 is the only Volume). Unlit interior areas fall to the near-black sky ambient. Options: APV bake with lighting scenarios (lit / blackout / aux power), or rely on SSGI plus low-intensity no-shadow fill lights per room. Add HDRP local Volumes per room (natural home: `BuildRoomReflectionProbe` createInteriorVolume branch K:774-787) for interior exposure/fog/indirect multipliers, or switch Exposure to Automatic Histogram with per-preset limits.
4. **Reflection probes (K:746-790).** (a) Captured once (`RealtimeMode.OnEnable`) in the pre-blackout lit state, so dark rooms keep bright reflections after the blackout. Switch to `OnDemand` and call `RequestRenderNextUpdate()` after `LightGroupController.SetGroup` fades, or bake per state. (b) Capture culling mask is the default -1 (package Runtime/Utilities/CameraSettings.cs:284). The lobby probe therefore sees the 45 grey RainBlocker slabs 0.30 m above the skylight glass, mirrored in the wet floor. Set `hdRefl.settingsRaw.cameraSettings.culling.cullingMask = ~(Mask(Viewmodel)|Mask(RainBlocker))`. (c) `multiplier 0.45` and colour clear (no sky) dim glossy surfaces; the lobby/menu probes behind glass should probably clear to sky. (d) Exteriors have no probes.
5. **Rain-blocker slabs = the 62 "grey DefaultHDMaterial renderers"** (K:792-807; 17 more in MainMenu). The game camera hides them (A:597, A:1507). Any other camera without the 12/13 mask shows them: aerial_vc_close.jpg renders the lobby roof as a flat grey slab with the three broken-pane holes. Do not "fix" them by material; mask them in capture cameras and probes (the rain occlusion camera needs them rendered).
6. **Lightning leaks indoors (A:762-774).** Directional 55 lux with `shadows = None`, and no indoor check (Scripts/Core/AtmosphereController.cs:302-306). At EV 0.6 every flash whites out corridors through solid roofs. Enable (low-res) shadows on `LightningFlashLight`, or scale the flash by an indoor factor (InteriorZoneVolume / rain occlusion).
7. **Exterior silhouettes read as grey boxes.** `BuildBoxRoomShell` ceilings double as roofs; 8 rooms use untextured MAT_PlasterClean (dump/materials.txt map=NONE), with no parapet or roof finish. Add a roof-cap box with its own material plus a parapet in BuildBoxRoomShell (K:470-479).
8. **Emissive bits ignore power state / carry no content.** Keycard LEDs (K:375-379) and the shutter `BottomLip` EmissiveAmber (K:346) are not LightGroupMembers, so they glow during blackouts. Overhead door signs and the menu EXIT sign are blank emissive plates (K:381-384, K:823, A:1385). The palette already has textured sign materials (MAT_SignE0, MAT_SignStaffOnly in the dump); use them and register the plates via `AttachLightGroupMember`.
9. **Presets live in two places** (A:807-896 vs Scripts/Core/AtmosphereController.cs:163-252) and the live value suggests the code defaults (section 3). GoldenDay sepia = 4200 K x filter (1,0.92,0.80) x fog albedo (0.85,0.72,0.58) at both sites; DawnCoast fog is also rewritten into Preset_DawnCoast.asset every build (A:2222-2242).
10. **MainMenu**: all 7 lights candela and clipping; backdrop ridges are 72x26 m single-tile boxes (A:1396-1398); 55 lux unshadowed lightning every ~12-29 s; gradient sky near black. Rebalance after fix 1, swap ridges for rock meshes or terrain cards, and capture the current menu (the gemqa shot is stale).
11. **Camera**: FOV 78 vertical (~110 deg horizontal) for world and viewmodel (A:457, 594) vs Godot default 74 (settings.gd:20). HDAdditionalCameraData only sets TAA (A:599-600): no physical camera, no TAA quality/sharpening.
12. **Workflow traps**: any hand edit in the scenes or runtime profiles is lost on rebuild (section 1). The edit-mode jump swaps the global profile to a Preset_*.asset (A:1729-1742), so never save the scene after an edit-mode jump; judge the look in Play mode. The spark material is created with raw `SetFloat` surface settings and no HDRP validation (A:1181-1186). `ShutterSparksVfx` floats at scene root at the fallback (-28,3,-15.5) because no `lobby_shutter_sparks` anchor exists.
